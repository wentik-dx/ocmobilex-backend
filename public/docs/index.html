Docs for OCMX

OCMX is the dependency-free JSON backend behind OpenCode Mobile. It runs on Cloudflare Pages Functions, stores everything in one KV namespace, and powers accounts, bug reports, ideas, shared chats and publishing.

01What OCMX is

The Android app talks to https://ocmobilex.pages.dev. Every route is a plain ES-module Pages Function — no npm packages, no build step, no framework. Responses are JSON with a boolean ok; storage is a single KV binding named OCMX.

Zero dependencies

WebCrypto only: PBKDF2-SHA256 password hashes and stateless HMAC-SHA256 session tokens.

One backend, two surfaces

JSON at /api/* plus server-rendered public pages at /shared/chat/*, /p/* and /v/*.

Made for the app

Verified ocmx:// and https:// deep links open the matching screen instead of a browser tab.

Community-safe

Roles, moderation reports, rate limits, content policy and legal documents are built in.

02Accounts & roles

A username is 3–24 characters of A-Z a-z 0-9 _; a password is 8–200 characters. The first account ever registered — and the reserved name MrWentik — becomes owner. On a fresh deployment the owner can also be created idempotently with POST /api/seed using the X-Owner-Token secret.

LEVEL 1user
Register, publish, share, report, vote.
LEVEL 2mod
Moderation queue and decisions.
LEVEL 3admin
Staff powers; cannot touch owner role.
LEVEL 4owner
Reports, statuses, roles, bans, seed.
Sessions are stateless tokens valid for 30 days. Deleting the account removes the record, which invalidates every token issued to it. Muted accounts cannot create content; banned accounts cannot sign in.

03The Three Pillars

Everything shared through OCMX is covered by the Terms of Service and Privacy Policy — no illegal, hateful, harassing, infringing or explicit content, and never upload secrets.

PILLAR 1 Bug reports

POST /api/bugreport/send accepts title, version, steps, expected/actual behaviour, device, severity (low|normal|high|critical), contact and logs. Owner bumps the status through open → triaged → in_progress → resolved (or wontfix / duplicate). One report per 3 minutes per IP and per account.

PILLAR 2 Ideas

POST /api/suggestidea/send takes a title, description, category (feature|design|performance|other) and impact (low|normal|high). Anyone can browse and sort by votes or date; signed-in users vote with POST /api/suggestidea/vote — same direction toggles off, opposite switches.

PILLAR 3 Shares + publishing

POST /api/share/chat stores a transcript under a 32-character code with per-chat write / pin / editSession / deleteMessages / invite permissions. POST /api/publish stores HTML (512 KB) or image/audio (5 MB) and serves it at /p/<id> with a sandboxed CSP.

Supporting systems: moderation (user + AI reports, warn / mute / ban / delete), legal documents, and the status probe.

04Quick start

# health
curl https://ocmobilex.pages.dev/api/status

# register — returns { ok, token, user }
curl -X POST https://ocmobilex.pages.dev/api/account/registernew \
  -H 'Content-Type: application/json' \
  -d '{"username":"Wentik","password":"********","confirmPassword":"********"}'

# login — save the token
curl -X POST https://ocmobilex.pages.dev/api/account/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"Wentik","password":"********"}'

# who am I?
curl https://ocmobilex.pages.dev/api/account/me \
  -H "Authorization: Bearer $TOKEN"

Full request bodies, response shapes, auth headers, CORS and rate limits live in the API reference.

05Deep links

The app registers the ocmx scheme for every link, and Android App Links verify https://ocmobilex.pages.dev for share and publication paths via /.well-known/assetlinks.json.

Deep linkOpensNotes
ocmx://accountAccount screenSign in, profile, avatar, links.
ocmx://shareShare chatPublish a transcript.
ocmx://publishPublishHTML, image or music.
ocmx://bugBug reportSend logs and severity.
ocmx://ideaIdea boardBrowse and vote.
ocmx://shared/chat/<code>Shared chat32-character alphanumeric code.
ocmx://publish/<id>Published item16-character alphanumeric id.
https://ocmobilex.pages.dev/shared/chat/<code>Shared chatVerified App Link; web viewer fallback.
https://ocmobilex.pages.dev/v/<id>Published item viewerVerified App Link; wrapper page.
https://ocmobilex.pages.dev/p/<id>Raw payloadVerified App Link; HTML is sandboxed.
On desktop these links stay in the browser; the public pages render a full viewer anyway. On Android the app tries to open automatically once per browser session with an “Остаться” (stay on web) escape hatch.
