Markdown vocabulary v2.11

The OpenCode Mobile chat renderer is dependency-free: everything is HTML-escaped first, then a small set of custom tags is turned into interactive widgets. This is the exact vocabulary from web/src/markdown.js and the app's AGENTS.md, updated for v2.11 — including the new extended vocabulary and mandatory correctness rules.

03Cards & buttons

<vizembed>block

Bordered Markdown card. Attributes: title, icon, color, footer, content. Literal \n and \t in content become real breaks/tabs; escape quotes as \".

<vizembed title="Build summary" icon="check" color="#34d399" footer="2 min ago" content="**All green.**\n\n- 3 packages built\n- 0 errors">
<vizbtn>inline

Button that sends an exact message to the agent. Attributes: title (or label, default “Send”), icon, message (or prompt).

<vizbtn title="Run the tests" icon="play" message="Run the full test suite and summarize failures">
<vizreply>inline

Dotted-underline reply link. Attributes: title (default “Reply”), reply (or message).

<vizreply title="Explain the error" reply="Explain the error in the last tool output">
<vizschedule>block

Creates an app-side scheduled message. Attributes: name/title, prompt/message (required), delay (e.g. 30m), optional every and at. Renders a “Create schedule” button.

<vizschedule name="Morning check" prompt="Check the build status." delay="30m">
<vizproject>block

Project badge; tapping opens that project's chat. Attributes: id (project id from /api/project), title/name, icon, color, description.

<vizproject id="proj_123" title="Website" icon="folder" color="#38bdf8" description="Marketing site">
<vizcalc>block

Inline tappable calculator with 0-9, ., +, -, *, /, C, =. Optional title.

<vizcalc title="Quick math">

04Progress, logs & separators

<updbar>block

Live progress strip; also feeds the global bar under the app header. now=0..100 (a % suffix is tolerated, invalid values become 0). 100 turns lime, flashes and shows “Update complete · 100%”. stuck="message" renders a red pulsing blocked state. Re-sending the same value is a no-op. Emit the tag bare — never wrap it in updateProgress:"…" or labels; see correctness rules.

<updbar now=10>
<updbar now=60>
<updbar now=100>

<updbar stuck="Auth failed. reworking..">
<utils> / <log>block

Compact log-style embed, usually written after an <updbar>. Attributes: title, content (\n → newline), color, level, footer, icon. Level tints the card: error/fail/bad → red, warn/todo/writing → amber, info/ok/done → green.

<utils title="Build" content="vite build…\nOK · 3 chunks" color="#2dd4bf" level="info">
<separator> / <divider>block

Styled horizontal rule. Attributes: color (hex, rgb, hsl or CSS name) and type, default line. In v2.11 this is superseded by <sep> — see v2.11 vocabulary; the old color/type arguments are dropped.

<separator color="#38bdf8" type="gradient">

Legacy types:

linedasheddotteddoubledotstarheartdiamondwavearrowgradientornament

05Shortcuts, releases & ions

<desklink> / <desktop>block

Creates a real Android home-screen shortcut. Attributes: title, action, args, color, icon. Actions: msg / prompt / ask (send text to a session), session (open), open (navigate), toast, notify. args is a key:value DSL joined by |||.

<desklink title="Say Hi Me" action="msg" args="msg:Hi, Ai!|||session:ses_jsjsis" color="#2dd4bf">
<rel> / <update>block

App-update status panel. Attributes: id (release id), tag, optional version, title, from, color. Each item must be on its own line. AI may only emit Indev, MADE, Failed; on writing is the app's own draft state. MADE releases expose APK download/install actions.

<rel id="rel_123" tag="MADE" version="2.9.1" />
<ion=name>inline

One-shot full-screen reaction; one per reply, marker hidden, so surrounding text must stand alone. Inside inline code it stays literal.

<ion=party> Release shipped!

Built-in names:

angryragehappygrinlaughloveblushsadcryshockwowthinkcoolwinksleepysickdizzydeadpartyevilshyrichneutral

Custom ions are created in Settings → Custom ions with color1,color2[,color3],title,emoji; the chosen name becomes the tag handle.

06Images & HTML visualizations

<img=CODE> / <image=CODE>block

Renders a chat image stored on the device. The app tries .png, .jpg, then .jpeg. Missing files show an error card.

$HOME/opencode-mobilex/sessions/<sessionID>/generatedx/img/<CODE>.png

<img=abc12def34ghi56>
<html-vizualize=CODE>block

Loads a self-contained HTML file from Termux home into a sandboxed iframe. Inline <style> and <script> are allowed; remote scripts/stylesheets and network requests are blocked. Keep it under 512 KB; the iframe auto-sizes via the oc:viz-height reporter. Shared styles are injected from ~/opencode-mobilex/yiks/main_htmls_style.css.

$HOME/opencode-mobilex/sessions/<sessionID>/inMsgHtmls/<CODE>.html

<html-vizualize=abc12def34ghi56>

Codes match [A-Za-z0-9_-]{8,32} — conventionally 15 lowercase alphanumeric characters. Always write files with the current session id.

Timestamps & dates

<time:{UNIX}:{l|f|t|d}>newno closing tag

Timestamp rendered as grayish-white text on a gray background. Mode: l = time left, f = full, t = time only, d = date only. Use the getUnixTimeByDate client tool to get Unix seconds fast.

<time:1732147200:f>
<cdown:{UNIX} %clr>newno closing tag

Countdown. Colour by remaining threshold: 51–100% green, 11–50% yellow, 1–10% red, 0% #ff0000, with a gray outline. %clr overrides the colour.

<cdown:1732147200 %clr:"#38bdf8">

Text decoration

<strk %clr:"#ffffff" %size:"1">TEXT</strk>new

Stroked (outlined) text. %clr = stroke colour, %size = stroke width.

<strk %clr:"#ffffff" %size:"1">BOLD</strk>
<ftfm:{FONTFAMILY}>TEXT</ftfm>new

Custom font family for the enclosed text.

<ftfm:JetBrains Mono>hello</ftfm>
<grad c1:"#" c2:"#" … c10:"#" %anim:0.3 %glw %pul:0.2>TEXT</grad>new

Gradient text. Up to 10 colour stops c1:"#" … c10:"#". Modifiers: %anim = animation seconds, %glw = glow, %pul = pulse seconds.

<grad c1:"#8b7bff" c2:"#4fb3ff" %anim:0.3 %glw %pul:0.2>v2.11</grad>
<rainbow %anim:0.3 %glw %pul:0.2>TEXT</rainbow>new

Rainbow text with the same animation modifiers as <grad>.

<rainbow %anim:0.3 %glw>RAINBOW</rainbow>
<ctxt:{glitch|neon|wave|flip|pulse|smallcaps} %anim %sp:0.2 %glw %pul:0.2>TEXT</ctxt>new

“Cool text” effect. Effect names: glitchneonwaveflippulsesmallcaps Modifiers: %anim, %sp (speed), %glw (glow), %pul (pulse seconds).

<ctxt:neon %sp:0.2 %glw>NEON</ctxt>
<gradbg c1:… c10:… %anim %glw %pul>TEXT</gradbg>new

Gradient background using the same colour stops and modifiers as <grad>.

<gradbg c1:"#14141f" c2:"#1b1830" %anim:0.3>BG</gradbg>

<align:"r|l|c">TEXT</align>new

Alignment: r right, l left, c centre. REPLACES <center> — </center> is removed from the vocabulary (see correctness rules).

<align:"c">centered</align>

<kbd>SHIFT + F11</kbd>

Task-list checkboxes. Markdown forms: - [x] checked, - [ ] unchecked. Tag forms: <cbx:x>TEXT</cbx> checked, <cbx>TEXT</cbx> unchecked.

- [x] done

Navigation & files — no closing tag

Never append a closing tag to <ses>, <dload>, <load>, <spline>, <stpr>, <i> or <file>.
<ses:{SESSION_ID} %a:"ALT">newno closing tag

Session mention. Tapping it opens that session. %a sets the alt text.

<ses:ses_jsjsis %a:"Bug chat">
<dload:{PATH|URL} %a:"ALT">newno closing tag

Download on click; shows “Show in folder” when the download finishes.

<dload:/storage/emulated/0/OpenCode_Directory/app.apk %a:"APK">
<load:{URL} %a:"ALT">newno closing tag

Load media inline.

<load:https://example.com/clip.mp4 %a:"clip">
<spline:1"N1 Alt",5,19,… %a:"ALT" %clr:"#...">newno closing tag

Sparkline: comma-separated values, each optionally prefixed with an index and a quoted label. %a = alt text, %clr = line colour.

<spline:1"Mon",5,19,8 %a:"chart" %clr:"#34d399">
<stpr:3-5 %clr:"#...">newno closing tag

Stepper. %clr sets the colour.

<stpr:3-5 %clr:"#fbbf24">
<i:{ICON} %clr:"#...">newno closing tag

SVG icon from the ~500-name icon set. An unknown icon renders a blue ? circle. %clr sets the colour.

<i:rocket %clr:"#8b7bff">
<file %p:"PATH" %a:"ALT">newno closing tag

Open a file in the file manager (NOT Termux). %p = path, %a = alt text.

<file %p:"/storage/emulated/0/Download/note.txt" %a:"note">

Anchors, socials, separators, workflow

<anch id:"..." name:"..." icon:"..." clr:"#...">TEXT</anch> + <toanch:{ID}>TEXT</toanch>new

Anchor target plus an underdot-highlighted jump link. Clicking <toanch> scrolls to the matching anchor.

<anch id:"sec1" name:"Section 1" icon:"star" clr:"#8b7bff">Section 1</anch>
<toanch:sec1>go to section 1</toanch>
<soc:{yt|tg} {%v / %c / %sv / %app / %ch / %us / %mg}>TEXT</soc>new

Social preview card. Providers: yt (YouTube), tg (Telegram) for now; more later. Modifiers: %v, %c, %sv, %app, %ch, %us, %mg — pick the preview flavour.

<soc:yt %v>https://youtu.be/xyz</soc>
<sep %grad1:"#" %clr:"#" %stl:"..." %a:"...">newno closing tag

Separator. This is the ONLY form now — the old <separator color="…" type="…"> arguments are dropped. %grad1 sets the gradient start (repeat for more stops), %clr the colour, %stl the style, %a the alt text.

<sep %grad1:"#8b7bff" %grad2:"#4fb3ff" %stl:"gradient" %a:"divider">
<wflow %s1:"Text" %s1i:"icon" %s2:"Text" %s2i:"icon" …>newno closing tag

Workflow. Each step sN has text and an optional icon sNi.

<wflow %s1:"Plan" %s1i:"brain" %s2:"Build" %s2i:"code" %s3:"Ship" %s3i:"rocket">

08CRITICAL — markdown correctness rules read first

These rules mirror §0.1 of the canonical AGENTS.md. Dumb markdown mistakes break the chat UI — get these right every time before you hit send.

  1. Never emit stray closing tags. </center> is REMOVED from the vocabulary — use <align:"c">TEXT</align>. Any unknown or malformed closing tag must be silently dropped by the app, never shown as literal text.
  2. <color=#RRGGBB> MUST be closed with </color>. Never write <color=#fff TEXT — always <color=#fff>TEXT</color>. Same for other paired tags (<bg>, <size>, <align>, <strk>, <ftfm>, <grad>, <rainbow>, <ctxt>, <gradbg>, <cbx>, <soc>, <anch>, <toanch>, <kbd>).
  3. <updbar> is emitted BARE: <updbar now=40>. NEVER write updateProgress:"<updbar now=40>" and never wrap it in prose or labels.
  4. These tags do NOT take a closing tag — never append </…>: <ses>, <dload>, <load>, <spline>, <stpr>, <i>, <file>.
  5. When unsure, use plain Markdown. Prefer the exact syntax shown here; never invent a tag — invented tags render as literal text.
A single stray </center>, an unclosed <color> or a labelled <updbar> is exactly the kind of error these rules prevent. Full agent reference: AGENTS.md §0.1 and §23.

09Renderer rules worth knowing

  • Everything is escaped before markup is applied, so model output cannot inject arbitrary HTML.
  • Unknown or malformed closing tags (for example </center>) are silently dropped — they never appear as literal text.
  • Embed tags are only rendered as blocks when they sit on their own line; otherwise they are inline widgets.
  • Parameters are parsed as key="value" pairs; \" escapes a quote inside a value. Colour values accept hex, rgb(), hsl() or CSS names.
  • In reasoning blocks, embed tags and diagnostic code fences about them are suppressed — the app strips “thoughts about using” <img>, <vizembed>, etc.
  • <details> bodies are rendered recursively, so Markdown and nested tags work inside them.
  • Spoilers must not contain | or line breaks, and do not work inside table cells.
